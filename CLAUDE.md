# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What This Is

A Claude Code skill (`aso-appstore-screenshots`) that guides users through creating high-converting App Store screenshots. It is invoked via the `/aso-appstore-screenshots` slash command from within a user's app project.

## Architecture

The skill is **HTML-first**: Claude authors per-app HTML/CSS design files (the design judgment), a headless browser renders them at exact App Store dimensions (the pixels), and a generative image model is demoted to an opt-in tool for isolated pieces only. There is no full-canvas AI render and no paid call in the happy path — every render costs $0 and is reproducible for a given renderer/Chromium version (structurally identical, not byte-identical across versions).

The skill is composed of:

- **SKILL.md** — The skill prompt. Defines a multi-phase workflow: Recall → Benefit Discovery → Screenshot Pairing → iPhone Generation → optional iPad Extension / optional Localization. Uses Claude Code's memory system to persist state across conversations so users can resume mid-workflow. Generation is a design-authoring loop: copy/adapt the shipped base template (`assets/html/`) into the user's project as `screenshots/design/` (a per-app `set.css` design system + one HTML page per shot), render each page with `agent-browser`, and refine in a free render → Read → adjust QA loop. The iPad and localization phases are opt-in; their full workflows live in `references/` and SKILL.md loads them on demand.
- **references/ipad-extension.md** — The full opt-in iPad phase (offered only after the iPhone set is approved). Reuses the benefits, brand colour, and the iPhone set's design language; no re-discovery. Adds an iPad design system at `screenshots/design/ipad/` (its own `set.css` with the iPad frame variant + a bumped type scale; fonts are NOT re-vendored — its `@font-face` urls point at the shared `../assets/` tree), renders at viewport `2064 2752`, and promotes approved renders to `screenshots/final/ipad/0N-<slug>.png`.
- **references/localization.md** — The full opt-in localization phase (offered after a device's English set is approved). ONE flow: translate the marketing headlines (LLM, free), set `<html lang>` per locale page, vendor a heavy CJK webfont (Noto Sans JP/KR/SC Black) for ja/ko/zh into the shared `design/assets/` tree via a set-wide `@font-face` + `:lang()` rule in `set.css`, swap in localized simulator raws when the app UI is localized (else keep English raws with translated headlines), and re-render per locale. Zero paid calls. The `simctl clone` + `AppleLanguages`/`AppleLocale` recipe is kept (for *capturing* localized raws). Outputs under `screenshots/final/<locale>/` (iPad: `screenshots/final/ipad/<locale>/`).
- **references/genai-pieces.md** — The full opt-in genai-piece flow (loaded only when the user requests a piece): backend resolution (env → memory → detection — the only place backend selection runs), the `enhance.py`/`cutout.py` invocations, key-colour guidance, compositing as one `<img>` layer (a hero-breakout piece takes `class="piece"` so base.css's `img.piece` rule fills the card window instead of applying the raw-offset math), and per-piece failure handling. SKILL.md keeps only the use-case summary + pointer.
- **assets/html/** — The shipped **base template** (high design floor). `base.css` is the design system: reset, exact-canvas sizing (iPhone 1290×2796 / iPad 2064×2752 via `body.iphone` / `body.ipad` token blocks), a uniform type scale as custom properties (`--verb-size` / `--desc-size` with a `--headline-side-pad` ≥6% edge margin), a fully CSS-drawn device frame (bezel/radii/shadow behind vars; Dynamic Island on iPhone and iPad camera-dot via one shared `.device::after` pseudo-element sized per device), and the `.breakout` real-pixel crop pattern (`box-sizing: content-box` `overflow:hidden` window that is exactly crop×zoom, with the outer card = crop×zoom + 2×3px border; offset/scaled `<img>` driven by `--crop-x/y/w/h` and `--zoom`; the `.breakout` div nests INSIDE `.device` after `img.screen` and AUTO-OCCLUDES — it centres over its crop's on-screen spot, derived from the crop vars + a per-device `--screen-scale` number, with `--shift-x/y` the only manual nudge; crops are MEASURED against the raw's real pixels and inset `i` (8-12px) inside the panel bounds; full-panel coverage needs `zoom ≥ screen-scale × P/(P − 2i)` per axis (~0.9 rule of thumb; `zoom ≥ screen-scale` alone is NOT enough), a sub-block card need only cover its own crop's footprint (`zoom ≥ screen-scale`); QA judges softness at 1:1 — the full doctrine is canonical in SKILL.md's Breakout flow, other files summarize + point there). `@font-face` loads bundled Inter via the relative url `../fonts/InterDisplay-Black.otf` (rewritten to the vendored copy at runtime). `ready.js` is the **shared fail-closed readiness gate** — ONE copy, loaded by every page via `<script src="ready.js">` and vendored next to each `set.css` at runtime (never inlined per page): it adds `body.ready` only once `document.fonts.ready` resolved, every `<img>` decoded with `naturalWidth > 0`, every copy of the raw matches `--raw-w` (`img.screen` + same-src breakout imgs; a genai piece with its own src is exempt), the headline font passes `document.fonts.check` (a CJK headline still resolving to the Latin face also fails), the `set.css` custom properties AND the body background resolve (a malformed `--bg` fails instead of rendering transparent), and the headline fits without `overflow:hidden` clipping; on any failure it adds `body.render-error` + a `data-render-error` reason instead. `base.css` additionally paints a full-canvas magenta NOT-READY banner until `body.ready` exists, so even a timer-based capture (the fallback renderer) cannot pass a broken page as plausible. `iphone.html` / `ipad.html` are complete example pages with commented headline/screenshot/breakout slots loading `ready.js`. `README.md` documents the slots, custom properties, invariants, and render sequence. `placeholder-screen-iphone.png` / `placeholder-screen-ipad.png` are demo raws so the template renders standalone (replaced at runtime).
- **enhance.py** — Wrapper around the `google-genai` SDK that calls Google's Nano Banana Pro (default model `gemini-3-pro-image`, overridable via `--model`/`$GEMINI_MODEL`). **Narrowed opt-in role**: it is used ONLY for an isolated piece the deterministic pipeline can't produce (an irregular/non-rectangular extraction a CSS crop can't handle, content bleeding behind an element, a decorative piece the user explicitly wants invented, or a hero-shot breakout panel re-rendered bigger/crisper than the raw raster allows at an acceptable zoom), generated in isolation on a flat known-colour background and composited into the page as one `<img>` layer — never the full canvas. Takes `--prompt`/`--prompt-file`, zero or more `--image` flags (order preserved — **`--image` is now optional; prompt-only generation with no input image is allowed**, announced with a stderr note so an accidentally-dropped `--image` on the hero-breakout path can't silently invent UI), `--output`, an optional `--aspect-ratio`, and `--backend {gemini,codex}`. On undecodable model output it now **fails instead of writing raw bytes** to `--output`. The gemini backend accepts either `GEMINI_API_KEY` or `GOOGLE_API_KEY`; the `codex` backend (env `ENHANCE_BACKEND=codex`) shells out to the OpenAI `codex` CLI (no key, output validated as a readable image). Both backends are OPTIONAL prerequisites — resolved only when a genai piece is actually requested.
- **cutout.py** — numpy-vectorized (Pillow + numpy) chroma-key helper (PEP 723) for the genai-compositing step. Keys out a commanded flat background colour (`--color`, hex, 3- or 6-digit) and writes a transparent RGBA PNG so a genai piece can be composited without showing as a visible plate. `--tolerance` fully keys pixels within that Euclidean-RGB distance; a `--feather` band above tolerance ramps alpha for a soft edge. Existing input alpha is preserved. **Warns when the key never fully matched** (nothing went fully transparent — including the near-miss case where the background only grazed the feather band and a half-opaque plate remains) **or matched everything** (the tolerance ate the subject). Distance math runs squared in float32 with the sqrt confined to the feather band. The only surviving Pillow-compositing helper now that `compose*.py` are gone.
- **showcase.py** — Generates a showcase image showing any number of final screenshots side-by-side (the pipeline passes all finals, typically 3-5) with an optional GitHub link at the bottom. Used as the final step after a set is approved. Checks each `--screenshots` path exists first, **creates the `--output` directory if missing, closes the images it opens, and warns on mixed aspect ratios** (a mix of iPhone and iPad finals in one showcase). Works for both iPhone and iPad finals — point `--screenshots` at the right directory. (Self-contained Pillow script — it no longer imports a shared module.)
- **assets/fonts/** — Bundled Inter fonts (SIL OFL): `InterDisplay-Black.otf` for headlines (loaded via `@font-face`, vendored into the user's `screenshots/design/assets/` at runtime), `Inter-Regular.otf` for the showcase URL (showcase.py), and `LICENSE-Inter.txt`.

## The Render Pipeline (agent-browser)

Renders are produced by [agent-browser](https://github.com/vercel-labs/agent-browser) (headless Chromium via CDP). It is a **stateful, single session** — one global viewport, one active page — so renders are **strictly sequential**; never parallelize within a session. Per page:

```bash
agent-browser set viewport 1290 2796        # or 2064 2752 for iPad
agent-browser open "file://$PWD/screenshots/design/01-track-card-prices.html"
agent-browser wait "body.ready"             # the fail-closed gate (ready.js)
agent-browser screenshot screenshots/design/preview/01-track-card-prices.png
# QA passes + user approves → cp the preview over screenshots/final/01-….png
agent-browser close                          # once the batch is done
```

- The viewport IS the output size — no crop, resize, or aspect-ratio step. The render is natively the exact App Store dimension.
- **Readiness is explicit and fail-closed.** Every page loads the shared `ready.js` (one vendored copy next to each `set.css`), which adds `class="ready"` to `<body>` only once `document.fonts.ready` resolved, every `<img>` decoded with `naturalWidth > 0`, every copy of the raw matches `--raw-w` (genai pieces with their own src are exempt), the headline font passes `document.fonts.check` (CJK headlines must not resolve to the Latin face), the `set.css` custom properties and body background resolve (a `background-image` counts as painted), and the headline fits its box; on any failure it adds `class="render-error"` + a `data-render-error` reason instead. `agent-browser wait "body.ready"` is mandatory before every screenshot so a render never captures a fallback font, a broken image, or an unstyled page — a broken asset no longer sneaks through. A `wait "body.ready"` timeout means the gate failed: read `data-render-error` (JS-eval) for the named cause. Until `body.ready` exists, `base.css` covers the canvas with a magenta NOT-READY banner, so even a capture that skipped the wait is unmissable.
- **QA loop (replaces the old paid self-check/retry):** after each screenshot, Read the PNG and verify headline wording + ≥~6% edge margins, frame integrity, flat brand background, breakout coverage of its source (full-panel cards occlude the panel; sub-block cards cover their own crop's footprint) + crisp (not mushy) magnified text at the doctrine's target scale (a ≥ ~1.5× read, i.e. `--zoom` ≥ ~1.2; softness is the ceiling), and exact pixel dimensions with `sips -g pixelWidth -g pixelHeight`. Fix in CSS/HTML, re-render, $0 per iteration. Only clean renders are shown to the user.
- **Prerequisite is fail-at-point-of-use.** At the start of generation, run `command -v agent-browser` once (if missing: show `npm install -g agent-browser` and stop). There is NO standing smoke render — the first real render verifies the Chromium download for free, and the QA loop catches any breakage.
- **`agent-browser screenshot` can time out** (`Page.captureScreenshot`, ~2 min hang) on heavy pages — large viewports with multi-megabyte photo raws; SKILL.md's Failure handling gives the plain-headless-Chrome fallback. The fallback captures on a virtual-time budget rather than waiting on `body.ready`, but it stays fail-closed via the NOT-READY banner: a too-early or failed capture shows the banner instead of a plausible page.

## Running the Scripts

### enhance.py (opt-in genai piece, isolated only)

```bash
export GEMINI_API_KEY="..."   # or GOOGLE_API_KEY; only the gemini backend needs it

uv run enhance.py \
  --prompt-file piece-prompt.txt \
  --image reference.png \
  --output screenshots/design/assets/piece-raw.png
# add --backend codex (or ENHANCE_BACKEND=codex) to route through the OpenAI codex CLI (no key)
```

### cutout.py (chroma-key a genai piece for compositing)

```bash
uv run cutout.py \
  --input screenshots/design/assets/piece-raw.png \
  --color "#00FF00" \
  --tolerance 30 \
  --feather 4 \
  --output screenshots/design/assets/piece.png
```

### showcase.py (final side-by-side preview)

```bash
uv run showcase.py \
  --screenshots screenshots/final/*.png \
  --github "github.com/their-handle" \
  --output screenshots/showcase.png
# point --screenshots at screenshots/final/ipad/*.png for the iPad set; omit --github for no link
```

## Key Design Decisions

- **The LLM decides *what* and *where*; deterministic code renders the pixels.** Claude authors per-app HTML/CSS; a headless browser renders exact dimensions. An element can only smear if genai painted it — so almost nothing can smear.
- **Two separate outputs per set: source and finals.** Design files live under `screenshots/design/` (diffable, re-renderable `set.css` + per-shot HTML + vendored `assets/` + vendored simulator raws in `design/raw/` with URL-safe kebab-case names + a disposable `design/preview/` scratch dir); approved App Store-ready PNGs live under `screenshots/final/`. iPad nests under `design/ipad/` and `final/ipad/`; localized finals under `final/<locale>/` (iPad `final/ipad/<locale>/`). **Staging rule (unconditional):** every render — candidates, first renders, re-renders — writes to `design/preview/` and is `cp`-promoted to `final/` only after QA passes and the user approves; the output path never depends on recalled per-shot approval state.
- **Raws are preflighted and vendored.** `set.css` hardcodes `--raw-w` (1290/2064) and the breakout crops are measured in the raw's real pixels, so before authoring, `sips`-check every paired raw: all identical size + portrait (mixed → recapture on one device), 1290×2796 expected for iPhone (uniform-but-different → set `--raw-w` to the real width and recompute `--screen-scale`), and status-bar layout compatible with the CSS Dynamic Island. Then copy each raw into `design/raw/` (kebab-case) and point pages at the vendored copy — never a Desktop/original path.
- **The device frame is CSS-drawn and centralized.** Per-page markup is exactly the fixed snippet `<div class="device"><img class="screen" src="…"></div>`; ALL geometry/styling (bezel width/colour, radii, Dynamic Island / camera dot pseudo-element, shadow) lives in `set.css` behind custom properties, so a frame tweak is a one-file edit shared by every shot. `generate_frame*.py` and `assets/device_frame*.png` are retired.
- **The type scale is owned by `set.css`, never per-shot.** `--verb-size` / `--desc-size` are set once and apply to every page — this is how "same size on every screenshot" survives per-shot HTML. If a headline overflows (long German descriptors will), fix it set-wide (shrink the scale property or reword/re-wrap), never with a silent per-shot override. Headline text keeps ≥~6% padding from every canvas edge (`--headline-side-pad`, a plain design margin — there is no crop step to hide behind).
- **Breakout is a magnified real-pixel copy that must occlude its source.** Markup nests the breakout inside the device — exactly `<div class="device"><img class="screen" src="…"><div class="breakout" style="--crop-x/y/w/h; --zoom"><img src="<same raw>"></div></div>`. A CSS `overflow:hidden` window over an offset/scaled copy of the same raw `<img>`, with `border-radius` + drop shadow. Doctrine (mirrors SKILL.md): (1) **placement is AUTO-OCCLUDING, not eyeballed** — the card computes its centre from the crop vars + a per-device `--screen-scale` (the device-size knob — shipped values live in `base.css`'s device blocks; `--device-w` is derived from it as `raw-w*screen-scale + 2*bezel` in a shared `body` rule, so a frame resize can't desync placement) so it lands over its source; the removed `--breakout-top/left` are gone, `--shift-x/y` (default 0px) are the only manual nudges (recentre a sub-block card over the full panel, bounded so it never exposes the original of what the card shows — `|shift| ≤ crop·(zoom − screen-scale)/2` per axis for a sub-block); **coverage math:** with the crop inset `i` (8-12px) inside a panel of raw size `P`, a full-panel card fully occludes only when `zoom ≥ screen-scale × P/(P − 2i)` per axis (~0.9 rule of thumb — `zoom ≥ screen-scale` alone is NOT enough because of the inset), a sub-block card just needs `zoom ≥ screen-scale` to cover its own crop's footprint; (2) **CONTAINMENT** — since placement is derived, the panel choice is the placement, and the device deliberately bleeds off the canvas bottom, so only panels FULLY VISIBLE on the canvas are eligible: since `.breakout` is `box-sizing: content-box`, the outer card box is `centre ± (crop*zoom/2 + 3px border)` — compute it before committing and require it inside the canvas with ~40px+ top/bottom margin (bleed past the *bezel* is the point; clipping by the *canvas* edge is the defect). If the best panel is in the bled-off region: pick another on-canvas panel → use a raw where it sits higher → no breakout; never hand-place the card off its source; (3) **crops are MEASURED, not eyeballed** — sample the raw's pixels for the panel's true bounds and inset the crop 8-12px inside them (eyeballed crops leave a background stripe inside the card border); (4) if the panel is near-full-screen-width, crop a tight sub-block and magnify that; (5) the card READS `--zoom ÷ --screen-scale` bigger than its on-screen original — reach for a ≥ ~1.5× read (`--zoom` ≥ ~1.2, usually via a sub-block crop); softness is the ceiling, not a hard cap — QA judges it at 1:1 (mushy text → tighten the sub-block, back off toward the coverage floor, or use the opt-in genai hero-breakout path). **QA breakouts at 1:1:** check containment first (card box inside the canvas, no edge cut by the canvas edge — objective and cheap), then, since a full-canvas Read is downscaled ~2.7× and hides 10-30px defects, extract the breakout region + ~80px margin at native res and Read that (no source sliver past any edge, no background stripe inside the border, crisp text). Clean beats forced — use no breakout if nothing on screen reinforces the headline.
- **Vendoring policy — final renders load ZERO external resources.** Fonts (bundled Inter; heavy CJK webfonts for ja/ko/zh) and any icon SVGs are copied into `screenshots/design/assets/` before rendering. No CSS framework — vanilla CSS only. Re-renders months later aren't perturbed by CDN drift (structurally identical, though Chromium version bumps can shift antialiasing — re-render a whole set in one sitting when extending it late).
- **CJK is vendored + `lang`-tagged, not left to system fallback.** Every locale page sets `<html lang="ja">` / `"ko"` / `"zh-Hans"` etc. (avoids Han-unification glyph confusion) and localized CJK sets vendor a matching heavy webfont (Noto Sans JP/KR/SC Black) via a set-wide `@font-face` + `:lang()` rule in `set.css`. The old `.ttc`-scanning `font_for`/`contains_cjk` machinery is gone.
- **Renders are sequential and $0, reproducible within one renderer version.** agent-browser is a stateful single session; never parallelize within it. Renders are structurally reproducible for a given renderer/Chromium version, not byte-identical across versions — so record `agent-browser --version` with the set and re-render a whole set in one sitting when extending it later. Version policy: the first shot renders 2-3 free design directions, each authored as its OWN self-contained page (`01-<slug>.a.html` → `set-a.css`, `.b.html` → `set-b.css`, …, each carrying its own breakout markup) rendered to `design/preview/` — NO copy-over-`set.css` dance mid-exploration (that desyncs CSS from markup). The user picks one; on selection `cp` the winning stylesheet to `set.css`, write the canonical `01-<slug>.html` linking it, delete the candidates. That `set.css` locks for the whole set — consistency by construction; render the winner against the longest headline before locking. Subsequent shots render once + free iteration. No style template, no "styled against" bookkeeping, no never-switch-backends rule, no paid-call cost warnings.
- **genai is opt-in, per-piece, never full-canvas.** `enhance.py` (kept) generates an isolated piece on a flat known colour; it is composited as an `<img>` layer after either `cutout.py` chroma-keying or intentional framing as a visible rounded card. An artifact is one small rejectable element, not a poisoned canvas. Backend selection (env → memory → detection; recommend gemini; save the answer) runs ONLY when a piece is requested.
- **Fail-at-point-of-use prerequisites.** Only `agent-browser` is a hard prerequisite, checked cheaply with `command -v` up front and fully verified by the first real render. The gemini key / codex CLI are optional, resolved lazily when a genai piece is requested. The API-key prerequisite gates only the gemini backend.
- **Memory is central to resumability.** Benefits, screenshot assessments, pairings, brand colour, and per-device generation state persist across conversations. Canonical memory files: `aso_benefits.md`, `aso_screenshot_pairings.md`, `aso_generated_screenshots.md` (canonical home of brand colour + target display size + optional `Image backend:` line), `aso_ipad_pairings.md`, and `aso_localization.md` (may be app-prefixed). Generation state records the design dir, per-shot HTML file, breakout crop notes, render status, final path, and the `agent-browser --version` the set was rendered with — no style-template or "styled against" records. `aso_localization.md` keeps a per-locale translation table, the raws source per locale (localized simulator raws vs English fallback), and per-shot render status — no Flow A/B. Old memory (style-template lines, `-resized.jpg` finals) still parses on Recall; the skill reports it and offers a free whole-set re-render into the new pipeline.
